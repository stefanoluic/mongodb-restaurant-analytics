# V1 sema baze podataka

V1 predstavlja pocetnu semu baze podataka. Originalni CSV fajl je 
podeljen u cetiri povezane kolekcije. Sve kolekcije koriste isti `_id`, koji potice iz polja
`restaurant_link`.


## Kolekcije

V1 sema ima cetiri kolekcije:

```text
restaurants
restaurant_locations
restaurant_ratings
restaurant_classifications
```

Svaka kolekcija ima po jedan dokument za isti restoran.

```text
restaurants._id
restaurant_locations._id
restaurant_ratings._id
restaurant_classifications._id
```

Sva cetiri `_id` polja imaju istu vrednost za isti restoran.

## restaurants

Kolekcija `restaurants` sadrzi osnovne podatke o restoranu.

| Polje | Opis |
| --- | --- |
| `_id` | Jedinstveni identifikator restorana. Dobija se iz `restaurant_link`. |
| `restaurant_id` | Ista vrednost kao `_id`, ostavljena radi citljivosti. |
| `restaurant_name` | Naziv restorana. |
| `claimed_status` | Originalna vrednost iz CSV-a koja govori da li je restoran preuzet na platformi. |
| `is_claimed` | Boolean verzija polja `claimed_status`. |
| `price_level` | Originalni cenovni rang, na primer `$`, `$$ - $$$` ili `$$$$`. |
| `price_score` | Numericka verzija cenovnog ranga. Vrednost 1 oznacava nizi, 2 srednji, a 3 visi cenovni rang. |
| `price_range` | Tekstualni opis raspona cena, ako postoji u skupu podataka. |
| `awards` | Niz nagrada ili priznanja restorana. |
| `original_open_hours` | Originalni podaci o radnom vremenu, ako postoje. |
| `open_days_per_week` | Broj dana u nedelji kada restoran radi. |
| `open_hours_per_week` | Ukupan broj radnih sati nedeljno. |
| `working_shifts_per_week` | Broj smena rada nedeljno. |

## Veze izmedju kolekcija

Veze nisu definisane kao strani kljucevi, kao u relacionim bazama, vec se
ostvaruju preko iste vrednosti `_id` polja.

Primer veze:

```js
{
  $lookup: {
    from: "restaurant_ratings",
    localField: "_id",
    foreignField: "_id",
    as: "rating"
  }
}
```

To znaci da se dokument iz jedne kolekcije spaja sa dokumentom istog restorana
iz druge kolekcije.

## Zasto je V1 sporija

V1 je sporija zato sto su podaci rasporedjeni u vise osnovnih kolekcija, a nisu
unapred pripremljeni za konkretna analiticka pitanja. Zato upiti cesto moraju da:

- filtriraju veliki broj dokumenata;
- spajaju vise kolekcija pomocu `$lookup`;
- razmotavaju nizove pomocu `$unwind`;
- grupisu podatke pomocu `$group`;
- sortiraju velike medurezultate pomocu `$sort`.

V1 zato sluzi kao pocetna sema nad kojom se meri baseline, odnosno stanje pre
optimizacije.
